# 引き継ぎ指示: 散歩での実機テストまで（2026-11-22 作成）

あなた（Opus）は**オーケストレーター**として、このアプリを XREAL AURA の実機で散歩テストできる状態まで持っていく。
**実装は Sol に任せ**、あなたはタスクの分解・指示・レビュー・ビルド・実機確認・ユーザーへの報告を担当する。

まず次の3つを読むこと。

- [AGENTS.md](../AGENTS.md): 守るべきルール
- [PLAN.md](PLAN.md): 計画全体
- [UI.md](UI.md): 承認済みの UI 仕様（参照モックは [ui-mockup.html](ui-mockup.html)）

## 1. 目標と期限

- **ゴール: ユーザーが明日（2026-11-23）の散歩で、AURA の実機を使ってこのアプリを試せること**
- AURA の実機はユーザーの手元にある
- 期限が短いので、PLAN.md の Phase 0〜4 をそのまま全部やるのではなく、§3 の「散歩テスト用 MVP」に絞る

## 2. 最初にユーザーに確認すること（まとめて1回で聞く）

1. **Sol への委任方法。** このセッションのツールで Sol を直接呼べるなら（サブエージェントのモデル指定など）、それを使う。呼べない場合は「タスク指示書方式」にする
   - タスク指示書方式: あなたが `docs/tasks/T<番号>-<名前>.md` に指示書を書く → ユーザーが別のチャットで Sol に「この指示書を実行して」と渡す → Sol の作業が終わったら、あなたが差分をレビューする
2. **散歩に出る時刻。** 逆算して、§3 のどこまで入れるかを決める
3. **今夜のうちに、ユーザーにやってもらえる準備（§4）**

## 3. 散歩テスト用 MVP の範囲

| 優先度 | 内容 |
|---|---|
| **必須** | アプリが AURA で起動する。Full Space で HUD がヘッドロック表示される |
| **必須** | 左クラスタ（距離・歩行時間・住所）が UI.md §3.1 の位置と形式で出る |
| **必須** | 状態の切替（歩行中 / 停止中 / 高速移動 / 測位なし）が UI.md §5 のとおり動く。特に**高速移動時の非表示** |
| **必須** | 初回起動時の注意文（PLAN.md §2.4） |
| **必須** | デバッグビルドの角度ガイド（UI.md §7）。配置を実機で確かめるのに使う |
| 推奨 | ミニマップ（Google Maps のダークスタイル、heading-up） |
| 任意 | パックのタッチパッドで HUD の表示・非表示を切り替える |
| 任意 | フィールドログ（§6） |
| 今回はやらない | 追従モードの切替メニュー、配置プリセット、設定画面、Geospatial、フォアグラウンドサービス、Health Connect |

- **地図が SpatialPanel 内で表示できないと分かった場合:** UI.md §3.2 のとおりライトモードを1回だけ試す。それでも駄目なら、明日は地図なし（右クラスタ非表示）で行く。ほかの地図サービスへの切り替えはユーザーに相談してから
- **時間が足りない場合:** 「推奨」以下を削る。「必須」は削らない。安全に関わる挙動（中央クリアゾーン、高速移動時の非表示）は絶対に削らない

## 4. ユーザーにお願いする準備

- [ ] AURA（コンピュートパック）で開発者向けオプションと USB デバッグ（またはワイヤレスデバッグ）を有効にし、PC の `adb devices` で見えるようにする
- [ ] Google Cloud で Maps SDK for Android を有効にし、API キーを作る

  - キーは `local.properties` の `MAPS_API_KEY=` に、**ユーザー自身が書く**
- [ ] 散歩中の通信手段（スマホのテザリングなど）を用意する。AURA にはセルラー通信がない
- [ ] AURA を充電しておく

### ビルドと実機操作のメモ（この PC の環境）

- **JDK に注意:** PATH 上の `java` は Java 8（Oracle）。コマンドラインで Gradle を使うときは、`JAVA_HOME` を Android Studio 同梱の JDK 21 に向ける
  - 場所: `C:\Program Files\Android\Android Studio\jbr`
- **SDK:** `%LOCALAPPDATA%\Android\Sdk`
  - platforms: android-33 / 35 / 36 / 36.1
  - build-tools: 〜36.0.0
  - adb: `platform-tools\adb.exe`（36.0.2）
- **Android Studio:** 安定版のビルド 253 が入っている。実機があるので、XR Glasses のエミュレータ（Canary 版が必要）は必須ではない
- **位置の擬似テスト:** 実機で試す前に、`MotionClassifier` と `DistanceTracker` は記録済みの合成データを流して確かめる。高速移動は単体テストで再現する（実際に乗り物で試させない）

## 6. フィールドログ（任意）

閾値の調整に使うための記録。作るなら次のルールを守る。

- 端末内にだけ保存する。`adb pull` で取り出せるようにし、**リポジトリにはコミットしない**（.gitignore に追加する）
- 記録するのは時刻、状態、速度、精度、距離の増分だけ。**緯度経度と住所は記録しない**

## 7. 散歩前のリハーサルとユーザーへの注意

### 7.1 T7 のリハーサル（あなたがユーザーに手順を示して、一緒に確認する）

1. 室内: アプリが起動し、角度ガイドで配置が UI.md どおりか、中央が空いているかを見る
2. 玄関先など、安全に立ち止まれる屋外: GPS の測位が始まり、距離・時間・住所が出るか。立ち止まって5分、距離が増えないか
3. 短い距離を歩く: 歩行中 ↔ 停止中の切替、地図の回転を確かめる

### 7.2 散歩当日の注意（ユーザーに必ず伝える）

- 最初は公園など車の来ない場所で、ゆっくり試す
- 横断歩道・駅のホーム・人混みでは HUD を見ない。必要ならアプリを閉じる
- 視界の邪魔になる、酔う、と感じたらすぐ外す
- 自転車に乗りながら使わない

### 7.3 散歩後

- ユーザーの感想を聞き、PLAN.md Phase 4 のチェックリストに沿って `docs/field-test.md` に記録する（位置情報は書かない）
- 配置や閾値を変えたいという意見が出たら、変更案をまとめてユーザーの了承を取ってから反映する

## 8. 守ること（AGENTS.md の要点）

- UI.md と PLAN.md §2 の配置・閾値・状態ごとの表示は、ユーザーの了承なしに変えない
- 秘密情報（API キー、署名鍵）をコミットしない。betterleaks のフックを `--no-verify` で回避しない
- 実在の位置ログ（GPX、座標、住所）をコミットしない
- ドキュメントに書かれていない挙動は推測で決めず、実機で確かめて記録する
- 会話は日本語
