# T19a: 視界の端の立体の矢印（2026-11-23 ユーザー承認・見た目は暫定）

まず [README.md](README.md) の共通ルールを読むこと。T1〜T18b は main に入っている。追加機能の全体は [PLAN.md](../PLAN.md) §9、安全ルールは §2.5、表示の原則は [UI.md](../UI.md) §11。

## 目的

案内中、右クラスタの案内の2行（T18b）の左に、次に進む向きを示す立体の矢印を出す。見た目は暫定で、受け入れでユーザーに確認する。**UI.md と PLAN.md は変更しない**。

## 見た目

- 地面に寝かせた矢印を、斜め上から見たように描く（奥に向かって約 55° 傾けた平面の上の矢印を、透視投影で描く）。矢印は厚みのある板の形で、上の面と下の面の輪郭と、縦の辺だけを線で描く（ワイヤーフレーム）。面は塗らない
- 大きさは視角で幅 3° 程度。線は 1.5dp 程度、色は `#7FDBFF`、不透明度 70% 以下
- 位置は案内の2行の左。内側の端は右16°より外側に保つ（はみ出すなら、案内の2行ごと外側へずらす）。T18b の2行と同じく、ミニマップの大きさの変化に合わせて滑らかに動く
- 測位なしの間は `#888780`。高速移動中は消す
- 向きの変化は約 300ms で滑らかに回す（359° → 1° のような境目では短い方へ回す）。点滅や拡大などの動きは付けない

## 矢印の向き

- 矢印は「基準の向き」から見た、進む方向を指す（矢印がまっすぐ奥を指していれば直進）
- 基準の向き:
  1. T15 の北の向きの推定があり、不確かさが 15° 以下なら、**頭の向き**（北基準の方位）を基準にする。頭を左右に向けると、矢印は現実の進む方向を指し続ける
  2. それが無ければ、0.5 m/s 以上で動いているときの **GPS の進行方位**を基準にする
  3. どちらも無ければ矢印を出さない（案内の2行は出す）
- 進む方向:
  - 次の曲がり角まで 15m より遠いときは、今の位置から次の曲がり角への方位
  - 15m 以内では、曲がった先の道の向き（次のステップの最初の線分の方位）。GPS の誤差で曲がり角への方位が暴れるのを避けるため
  - 到着の表示中は出さない
- 更新は角度が 2° 以上変わったときだけ、最大 10 Hz（電池のため）

## 実装の方針

- 投影の計算（3D の頂点 → 2D の線分）は純粋な関数にして、単体テストで確かめる
- 描画は Compose の `Canvas`。HUD の全体を毎フレーム作り直さないよう、矢印の角度だけの状態に分ける
- 矢印の形・傾き・大きさ・色は定数1か所にまとめる（受け入れで調整するため）
- 自己診断のログ（例: `AuraNav`）に、基準の種類（頭 / GPS / なし）と矢印の角度を出す

## 確認手順

1. `./gradlew test assembleDebug` が通る（JDK 21）
2. 単体テスト
   - 投影: 角度 0° で奥向き、90° で右向き、-90° で左向きの線分になる。傾きの定数を変えると奥行きが変わる
   - 基準の向きの選び方（推定あり・不確かさ 15° の境目・GPS だけ・なし）
   - 進む方向の選び方（15m の境目）
   - 境目をまたぐ回転が短い方へ回る。2° 未満の変化では更新しない
3. Robolectric の表示テスト
   - 案内中に矢印が出る。基準が無いときは矢印だけ出ず、案内の2行は出る
   - 測位なしで灰色、高速移動で消える、到着の表示中は出ない
   - 矢印の内側の端が右16°より外側にある（`HudPlacementTest` に追加）
4. 既存のテストがすべて通る
5. **実機（adb）は使わない（インストールもしない）**
