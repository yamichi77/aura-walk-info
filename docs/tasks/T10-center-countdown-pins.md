# T10: 中央のカウントダウン、地図のピン、大きい地図の矢印（2026-11-23 ユーザー要望）

まず [README.md](README.md) の共通ルールを読むこと。T1〜T9 は main に入っている。装着しての確認で、ハンドトラッキングのつまむ操作が HUD のパネルの Compose `clickable` に届くことを確かめた（`docs/device-capabilities.md`）。

## 目的

装着して試したユーザーの要望で、次の3つを直す。仕様はユーザーが決めたもので、勝手に変えない。

1. 開始・終了のカウントダウンを、左クラスタの端ではなく、視野の中央に大きく出す
2. 地図に、Google Maps のような周りの場所のピン（お店や駅などのアイコン）を出す
3. 大きい地図の現在地の矢印が大きすぎるので、小さくする

## 1. 中央のカウントダウン

- 開始のカウントダウンと終了のカウントダウンの間だけ、視野の中央（左右 0°・上下 0°、1.5m）に、透明な背景のパネルを出す。HudPlacement で配置する
- 中身（上から順に、中央揃え）
  - 1行目: `開始` または `終了`（数字の高さの約1/3、`#9FE1CB`）
  - 2行目: 残りの数字 `3` → `2` → `1`（数字の高さが約4°になる大きさ、`#E0F7FF`）
  - 3行目: `タップでキャンセル`（数字の高さの約1/4、`#9FE1CB`）
- 出すときと消すときは約200ms のフェード
- 中央のパネルをつまむとキャンセル（`AuraInput` に `CLICK target=countdown source=...`）。左クラスタをつまんでもキャンセルできる（今までどおり）
- カウントダウン中の左クラスタは、カウントダウンを始める前の表示（待機なら `タップで開始` と住所、計測中なら距離・時間）のままにする。左クラスタにはカウントの数字を出さない
- カウントダウン中に右下の地図をつまんでも、大きい地図は開かない（`AuraInput` に `ignored-countdown`）
- 高速移動中は、他の HUD と同じく出さない（`hudVisualSpecFor` の `Fast` のとき）
- デバッグビルドの `DEBUG_TAP` に `--es target countdown` を足す

## 2. 地図のピン

- 右下の地図（ミニマップ）と大きい地図の両方に、POI（お店・施設など）と駅のアイコンを出す
  - ミニマップ: アイコンだけ（名前は出さない）
  - 大きい地図: アイコンと名前。名前の文字色は暗めの `#9FB8C8`、縁取りは `#000000`
- 道路名・地名など、POI と駅以外のラベルは今までどおり出さない。線路（transit.line）も出さない
- スタイルの JSON は、ミニマップ用と大きい地図用の2つにする（例: `map_style_dark.json` と `map_style_dark_bigmap.json`）。地面・道路・水域などの色は今のまま
- 地図の自己診断（`AuraMap`）の判定基準は変えない（明るい画素 25% 以下など）

## 3. 大きい地図の矢印

- 大きい地図の中央の矢印を、ミニマップ（歩行中・直径 8°）の矢印と同じ見かけの大きさ（角度）にする。今は円の大きさに比例しているため、直径 28° の円で大きくなりすぎている
- 色・形は今のまま

## 変えないこと

- 大きい地図の自動で閉じる時間（停止中30秒、それ以外10秒、高速移動ですぐ閉じる）は T9 のまま。実機で確認済み
- `MotionClassifier`、`DistanceTracker`、`WalkSessionControl` と `BigMapControl` の判定

## 確認手順

1. `./gradlew test assembleDebug` が通る（JDK 21）
2. Robolectric の表示テストで、カウントダウン中は中央のパネルに `開始` / `終了`・数字・`タップでキャンセル` が出て、左クラスタに数字が出ないこと。中央のパネルのクリックでキャンセルされること。カウントダウン中は地図のクリックで大きい地図が開かないこと
3. スタイルの JSON を読むテストで、ミニマップ用は POI と駅のアイコンだけ表示（名前は非表示）、大きい地図用はアイコンと名前を表示、どちらも道路名・地名・線路が非表示であること
4. 大きい地図とミニマップ（歩行中）の矢印の見かけの角度が同じであること（計算のテスト）
5. **実機（adb）は使わない（インストールもしない）。** 実機での確認はオーケストレーターがユーザーの装着中に行う
