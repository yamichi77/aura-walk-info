# T34: 案内中のカクつきを直す（空間の印の描き直しと、空の方位帯のパネルの作り直し）（2026-11-25 issue #1）

まず [README.md](README.md) の共通ルールを読むこと。T1〜T33 は main に入っている。**UI.md と PLAN.md は変更しない**（見た目・配置・閾値・状態ごとの表示は今のまま）。

## 背景（オーケストレーターの実機の測定）

- issue #1: 目的地を設定すると、案内中ずっと画面がカクつく
- 測定: atrace（`gfx view input dalvik aidl` とアプリのトレース）で、アプリのメインスレッドの `Choreographer#doFrame` の間隔を見た。AURA の表示は 72Hz（1フレーム 13.9ms）。XR の合成側（surfaceflinger の compositor、systemui の Filament）はフレームを落としていない。カクつきは**アプリのメインスレッドの遅れ**。HUD は Compose for XR の追従でフレームごとに頭に合わせているので、メインスレッドが止まると HUD が頭に遅れて引っかかる
- 室内では北の向きが求まらないので、空間の印と空の方位帯が出ず、カクつきも出なかった。デバッグの `SETTINGS` ブロードキャスト（`--ef north_offset 0 --ef north_uncertainty 5`）で北の向きを与え、案内中に表示を切り替えて比べた。ユーザーもグラス越しにカクつきを確かめた

| 案内中の表示 | 2フレーム（27.8ms）を超えた間隔の回数 | 最長の間隔 |
|---|---|---|
| 印と方位帯 | 毎秒 0〜6 回 | 51〜95ms（印を初めて出したとき 118ms） |
| 方位帯だけ | 頭を止めている間は 0 回、頭を回すと毎秒 1〜3 回 | 49〜97ms |
| 印だけ | 毎秒 0〜5 回 | 22〜44ms |
| どちらも出さない（VPS とカメラは動いたまま） | 0 回 | 17〜27ms |

### 原因

1. **空間の印（`StandingMarkPanel`）:** 印を出している間、0.1 秒ごとの更新で `StandingMarkArtwork.update` が絵を描き直す。1回の描き直しで、メインスレッドが `draw → postAndWait` で 17〜23ms 待つ（1024×1024 の面に、にじみの線を 24 回重ねて描く RenderThread の処理を待っている。ほかのパネルの描画の待ちは 2ms 程度）。`MarkArtwork` は大きさ（メートル）を含むので、頭や体が少し動くたびに値が変わり、毎回描き直している。一方 `onDraw` は絵を自分の幅と高さで正規化して描くので、テクスチャの中身はほとんど変わっていない
2. **空の方位帯（`SpatialSkyBand`）:** 頭を回して曲がり角が帯の端を出入りするたびに、`key(mark.kind)` の印の組み合わせが変わり（`TURN`・`DISTANCE` ↔ `EDGE_LEFT`/`EDGE_RIGHT`）、`SpatialPanel` を壊して作り直す。そのフレームで `Compose:recompose` 18〜48ms と `traversal` 22〜37ms、合わせて 46〜83ms 止まる。頭を回している間は 67ms ごとに標本が更新され、そのたびにパネルの位置の再構成も走る
3. **一度だけの止まり:** 印を初めて出すとき（アンカーとパネル3枚を同じ時点で作る。約 118ms）。案内中に大きい地図を閉じるとき（`SpatialNavGuidance` は大きい地図を開くと消え、閉じると作り直される。約 97ms）

## 決定事項

### 1. 空間の印の描き直しを減らす

- **テクスチャの中身が変わるときだけ描き直す。** 比べる値は、絵を自分の幅と高さで正規化した形（矢印の点の座標と線の太さの比、`near`、ピンの形と、見えている高さをテクスチャの行数にしたもの）にする。大きさの変化は今どおり `setScale` で行う
- 形が少しずつ変わる場合（曲がり角の向きを見る角度が変わるなど）の量子化の幅は、テクスチャの上で約 1 画素以下の差（見た目が変わらない範囲）を目安に決める。決めた値と理由を最終報告に書く。描き直しの頻度に上限が要るなら、その値と理由も書く
- それでも描き直すときのメインスレッドの待ちを減らす工夫（例: 別のスレッドで Bitmap に描いて差し替える）は、固定版のソースを見て判断してよい。ただし**見た目（線の太さ、にじみ、色、明るさ、クリップの位置）は変えない**。テクスチャの解像度やにじみの段数を変える必要があると判断したら、実装せずに最終報告の「未決」に書く
- デバッグビルドで、描き直しの回数と時間を `AuraSpatial` に出す（例: 描き直しがあった秒だけ `REDRAW mark=TURN count=.. maxMillis=..`）。座標は出さない

### 2. 空の方位帯のパネルを作り直さない

- 帯の印の組み合わせが変わっても `SpatialPanel` を作り直さない（例: 印の種類ではなく枠（スロット）ごとにパネルを持ち、中身と位置を入れ替える。使っていない枠は隠し、当たり判定を持たせない）。方位帯を出している間にパネルを作るのは、最初の1回だけにする
- 標本の更新ごとの位置の変更で、再構成と配置のやり直しが重くならないようにする。Compose for XR rc01 で、再構成なしにパネルの姿勢を変える方法（ラムダで値を読む修飾子、SceneCore のエンティティの姿勢を直接変える、など）があれば使う。固定版のソースで確かめて、選んだ方法と理由を最終報告に書く
- 位置（UI.md の方位帯の角度）、見た目、フェード、高速移動で消すこと、`MeasuredSkyPanel` の自己診断（`AuraPlacement SKYBAND PASS`）は今のまま

### 3. 一度だけの止まりを減らす

- 右の案内パネル（`SpatialNavGuidance`）は、大きい地図を開いている間も壊さずに隠しておく（T33 の大きい地図のボタンと同じ考え方）。大きい地図を開いている間は、今どおり見えず、触れない
- 空間の印のアンカーとパネル3枚は、同じフレームで作らない（例: 更新の1回ごとに1つずつ作る）。見え始めるまでの遅れが増えるなら、その長さを最終報告に書く

### 4. 計測のログ

- デバッグビルドで、HUD を出している間のメインスレッドのフレームの間隔を `AuraFrame` に出す。2フレーム（27.8ms）を超えた間隔があった秒だけ、`AuraFrame longestMillis=.. over28=.. nav=<idle|preview|guiding> marks=<出している印の数> sky=<帯の印の数>` の形で1行出す。計測そのものが負担にならないようにする（`Choreographer` のフレームコールバックか `withFrameNanos`）
- 座標や地名は出さない

## 確認手順

1. `./gradlew test assembleDebug` が通る（JDK 21）
2. 単体テスト: 印の絵の比べ方（大きさだけ変わったときは描き直さない。形が変わったら描き直す。ピンの見えている行数が変わったら描き直す。量子化の幅の内側の変化では描き直さない）
3. Robolectric の表示テスト
   - 方位帯の印が `TURN` → `EDGE_LEFT` → `TURN` と変わっても、パネルが増えたり作り直されたりしない（作った回数を数えられる形にする）。帯の印の位置は今と同じ
   - 右の案内パネルが、大きい地図の開閉で作り直されない。大きい地図を開いている間は見えない
   - 今の方位帯・案内・大きい地図・空間の印のテストが通る（合わせて直す）
4. **実機（adb）は使わない。** main のワークツリーには触らない。実機での測定はオーケストレーターが行う（上の表と同じ手順で、印と方位帯を出したまま頭を回しても、2フレームを超える間隔がほぼ出ないことを確かめる）
