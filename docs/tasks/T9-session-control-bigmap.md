# T9: 歩行の開始・終了と大きい地図（2026-11-23 ユーザー承認）

まず [README.md](README.md) の共通ルールを読むこと。T1〜T6 と T8（頭の回転中は HUD を消す）は完了して main に入っている。

## 目的

ユーザーの要望で、次の2つを入れる。仕様はユーザーが決めたもの（下の「決定事項」）で、勝手に変えない。

1. 歩行の開始と終了を、ユーザーの操作で行えるようにする
2. 右下の地図をタップすると、正面に大きい地図を出す

## 入力について（重要・未確認）

- T6b・装着確認の結果: `MainActivity` の `dispatchTouchEvent` などには、パックのタッチパッドのタップが**一切届かなかった**。ただしそのとき、ポインターが HUD のパネルに重なっていたかは分かっていない
- Android XR では、空間パネル（SpatialPanel）の中身は、ポインター（タッチパッドのカーソル）やハンドトラッキングのつまむ操作でクリックできるはず。その場合、イベントはアクティビティではなく**パネルの中の Compose** に届く。そこで操作は **パネルの中身の Compose の `Modifier.clickable` / `pointerInput`** で受ける
- パネルが操作を受け付けるために必要な設定（例: SpatialPanel の操作可否の指定など）があれば、実際のライブラリで調べて設定する
- 受け取ったクリックはすべて logcat（タグ `AuraInput`）に `CLICK target=<left|map|bigmap|outside> source=...` の形で出す。装着中の確認で、届くかどうかをこれで判定する
- **クリックが届かないと分かった場合に備えて、起動時の動きを切り替える定数を1か所に用意する:** `SessionStartMode.STANDBY`（起動は待機、操作で開始。既定）と `SessionStartMode.AUTO`（起動で自動開始。今までの動き）。デバッグビルドでは intent extra `--es startMode auto|standby` でも切り替えられるようにする

## 決定事項

### 1. 歩行の開始と終了

- **起動直後は「待機」。** 距離も時間も数えない（位置の取得・移動状態の判定・住所・地図は動かしておく。高速移動時の非表示も効かせる）
- 待機中の左クラスタ: 1行目に `タップで開始`（16dp、`#E0F7FF`）、その下に住所（1行、14dp、`#B5D4F4`）。距離と時間は出さない
- **開始:** 左クラスタをタップ → **3秒のカウントダウン**（`3` → `2` → `1`。数字は 32dp、その下に `タップでキャンセル` 14dp `#9FE1CB`）。カウントダウン中にもう一度タップするとキャンセルして待機に戻る。0 になったら新しい歩行を始める（距離・歩行時間・経過時間を 0 から）
- **終了:** 歩行中（計測中）に左クラスタをタップ → **3秒の終了カウントダウン**（`終了 3` → `終了 2` → `終了 1`、その下に `タップでキャンセル`）。もう一度タップでキャンセルして計測を続ける。0 になったら計測を止め、**まとめ**を出す
- **まとめ:** 左クラスタに、1行目 `おつかれさま`（14dp、`#9FE1CB`）、距離（数字 32dp + 単位 16dp）、`歩行 mm:ss`、`経過 mm:ss ・ 平均ペース`（100m 未満ならペースなし）、`タップで新しく開始`（14dp、`#9FE1CB`）。まとめを表示している間にタップすると、開始のカウントダウンに入る
- カウントダウン・まとめの表示中も、高速移動なら `高速移動中のため非表示` が優先、頭の回転中は消える（T8）
- 計測中の表示は今までどおり（UI.md §5）
- フィールドログは、歩行を開始するたびに新しい CSV にする。待機中とまとめ表示中は記録しない
- 初回の注意文は今までどおり（起動直後に左クラスタの位置に出す。注意文の表示中のタップは、注意文を閉じるだけ）

### 2. 大きい地図

- **開く:** 右下の地図（ミニマップ）をタップする
- **位置と大きさ:** 正面（左右 0°）、**下4°を中心に直径28°の円**（上10°〜下18°）。距離は他のパネルと同じ 1.5m。HudPlacement で配置する
- **中身:** ミニマップと同じダークスタイル・heading-up・中央の矢印。ズームは 16.5（広い範囲が見えるように）。円の枠は 1px 相当、`#E0F7FF` の 40%。不透明度は、歩行中 70%・停止中 100%（UI.md §5 と同じ）。開いている間、右下のミニマップは消す
- **自動で閉じる:**
  - 開いたときに停止中なら **30秒**、それ以外（歩行中・測位なし）なら **10秒** で閉じる
  - 開いている間に歩行中（または測位なし）になったら、閉じる時刻を「その時点から10秒後」と「今の閉じる時刻」の早い方にする
  - **高速移動になったら、すぐに閉じる。高速移動中は開けない**（タップしても開かない。`AuraInput` に `ignored-fast` と出す）
  - 頭の回転中は、他のパネルと同じく消える（T8 のレイヤー）。ただしタイマーは進める
- **手動で閉じる:** 大きい地図をタップする、または**地図の外をタップ**したら閉じる。地図の外のタップを受けるため、大きい地図を開いている間だけ、視野全体を覆う透明（何も描かない）のパネルを後ろに置き、そのクリックで閉じる
- 開く・閉じるのアニメーションは約300ms のフェード

## 作り方の目安

- 状態（待機 / 開始カウントダウン / 計測中 / 終了カウントダウン / まとめ）は純粋な Kotlin の状態機械にして、単体テストを書く（タップ・時間経過・キャンセル・高速移動との組み合わせ）
- `WalkSessionRepository` に、計測の開始（0 から）と終了（止めて値を保つ）を足す。位置の購読・移動状態の判定は待機中も続ける。判定ロジック（`MotionClassifier`、`DistanceTracker`）は変えない
- 大きい地図の開閉と自動で閉じるタイマーも純粋な Kotlin の状態機械にして、単体テストを書く（停止中30秒、歩行中10秒、開いた後に歩き出したら10秒以内、高速移動ですぐ閉じる・開けない、地図や外のタップで閉じる）
- 既存の intent extra（`fakeState`、`grid`、`selfcheck`、`capture`、`resetNotice` など）と再生（ブロードキャスト）は壊さない。`fakeState` を使うときは計測中として表示する（既存の確認スクリプトのため）
- デバッグビルドでは、ブロードキャストでもタップの代わりができるようにする（装着中の確認と自動テストのため）: `adb shell am broadcast -a io.github.yamichi77.aurawalkinfo.DEBUG_TAP -p io.github.yamichi77.aurawalkinfo --es target left|map|bigmap|outside`。T6a の再生と同じく shell の権限つきで登録する

## 確認手順

1. `./gradlew test assembleDebug` が通る（JDK 21）
2. Compose UI テスト（Robolectric）で、待機・カウントダウン・まとめの左クラスタの文字列と、大きい地図の開閉を確かめる
3. **このタスクでは実機（adb）を使わない（インストールもしない）。** ユーザーが寝ている間に進めるため、実機への書き込みは朝にユーザーと一緒に行う。代わりに、JVM と Robolectric のテストで、待機 → 開始カウントダウン → キャンセル → 開始 → 計測（T6a の合成ルート `walk_stop` を流す）→ 終了カウントダウン → まとめ、と、大きい地図の開閉（停止中30秒・歩行中10秒・`fast` ですぐ閉じる）を、仮想時間で通しで確かめる。実機で `DEBUG_TAP` を使う同じ流れは、`scripts/device-check.sh --only session` の項目として足しておく（朝に実行する）
4. `scripts/device-check.sh` に項目を足す
   - `--only input`: 「ポインターを左の数字に合わせてタップしてください」「次に右下の地図をタップしてください」「大きい地図の外をタップしてください」と順に表示し、各15秒待って `AuraInput` の `CLICK target=...` を確かめる（届いたら `PASS`、届かなければ `FAIL` と、そのとき出ていたログ）
   - `--only bigmap`: `DEBUG_TAP` で大きい地図を開いて、配置の自己診断（中心が 左右0°±1°・下4°±1°、直径28°）と、自動で閉じる時間を確かめる
5. 最終報告に、装着中に走らせる短いコマンド（`--only placement,headmotion,input,bigmap,session` など）と、クリックが届かなかったときに `SessionStartMode.AUTO` に切り替える手順を書く
6. 足した `device-check.sh` の項目は、実機につながずに確かめられる範囲（`bash -n`、関数単体を合成ログで呼ぶ、など）で確かめる

## 受け入れ条件

- 状態機械（開始・終了・まとめ）と大きい地図の開閉の単体テストがすべて通る
- 高速移動中は、大きい地図が開かず、開いていたらすぐ閉じる（テストで確認）
- 既存のテストがすべて通る
- UI.md・PLAN.md が上の文言で更新されている
