# T24: 信号機の情報を、発信源の場所の空間に「信号の柱」として出す（2026-11-24 ユーザー判断）

まず [README.md](README.md) の共通ルールを読むこと。T1〜T23 は main に入っている。**安全ルールは [PLAN.md](../PLAN.md) §2.5「信号機の情報」と「空間に置く印」（必読）**、見た目は [UI.md](../UI.md) §11「信号機の情報」と「空間に置く印」（どちらもオーケストレーターが更新済み。**変更しない**）。

## 背景（T20 の実機確認）

ユーザーから、頭に貼り付いた信号の表示（左の `信号 …` の行、地図の上の交差点の印）は見えない・要らない、BLE の発信源の場所の空間に状態を出してほしいと要望があった。参考の動画では、交差点の向こう側の空中に、状態の丸と残り時間のゲージが縦に並んだ柱が、現実の場所に固定されて浮かんでいた。

## 決定事項

- **やめるもの:** T17b の左クラスタの信号の行（起動後の初回の「信号は参考表示です」を含む）と、ミニマップ・大きい地図の交差点の印。関係するコードとテストを取り除く。T17a の受信・判定、空の方位帯（T19b）の交差点の印はそのまま
- **信号の柱:** T23 の空間の印の仕組みで、発信源の位置（T17a の電文の緯度経度）の地上 3〜5m に、空間に固定して出す。T23 の「信号機の印」（地上 7m の細い円）は、この柱に置き換える
  - 中身（UI.md §11）: 灯器ごとに1行。番号・状態の丸・状態の文字（`赤` / `青` / `青点滅` / `—`）・残り値のゲージ（1〜8 段。数字は出さない）。下に小さく `参考表示`
  - 色: 状態の丸は赤 `#E07A7A`、青 `#7FBFA8`、青の点滅は `#7FBFA8` の輪郭だけ、その他は灰色 `#888780`。赤と青は同じ明るさ・同じ大きさ。丸の中は 30% 以下で薄く塗る。文字とゲージは `#E0F7FF`。古い（1.5〜3 秒）ときは全体を `#888780`
  - 大きさ: 柱の幅は 0.6m 程度、1行の高さは 0.3m 程度（4 灯器で 1.2m 程度）。文字は、15m 先で読める大きさ（視角 1° 程度）を目安にし、定数にまとめる
  - 柱は常に利用者の方を向く（縦軸まわりにだけ回す。傾けない）
- **出す条件（PLAN.md §2.5）:**
  - T17a の判定が交差点を返しているとき（停止中・30m 以内・3 秒以内）
  - **停止中だけ、中央クリアゾーンの例外**。歩行中・高速移動になったら、フェードせずにすぐ消す
  - 仰角 5° の条件は使わない。ただし目線より下には出さない（柱の下端が目線より下に来る場合は、柱全体を上へずらして下端を目線の高さにそろえる）
  - 追跡なし・北の推定なしか不確かさ 15° 超え・GPS の精度 20m より悪い・空間の印の設定オフのときは消す（T23 と同じ）
- 判断の言葉（「渡れます」など）は出さない

## 確認手順

1. `./gradlew test assembleDebug` が通る（JDK 21）
2. 単体テスト: 柱の行の組み立て（灯器の順、状態の文字、ゲージの段数、残り値なし、4 灯器以上）、色（赤と青で明るさと大きさが同じ）、出す条件（停止中だけ、歩行中ですぐ消える、30m、鮮度）、目線より下に来るときの持ち上げ
3. Robolectric の表示テスト: 左クラスタに信号の行が出ないこと、ミニマップ・大きい地図に交差点の印が出ないこと、空の方位帯の交差点の印は残ること
4. `scripts/device-check.sh` の `pics` と `spatial` のチェックを、柱の表示に合わせて直す（`AuraSpatial` などのログで柱の状態を確かめる）。`bash -n` で文法だけ確かめる
5. 既存のテストがすべて通る
6. **実機（adb）は使わない（インストールもしない）**。オーケストレーターが受け入れ中なので、main のワークツリーには触らない
