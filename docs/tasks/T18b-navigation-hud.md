# T18b: ナビの表示と、音声・施設検索での目的地の入力（2026-11-23 ユーザー承認・見た目は暫定）

まず [README.md](README.md) の共通ルールを読むこと。T1〜T17b、T18a は main に入っている。追加機能の全体は [PLAN.md](../PLAN.md) §9、安全ルールは §2.5、表示の原則は [UI.md](../UI.md) §11。

## 目的

T18a のナビの状態（`NavState`）を HUD に出し、音声で施設名を言って目的地を選べるようにする。見た目は暫定で、受け入れでユーザーに確認する。**UI.md と PLAN.md は変更しない**。視界の端の立体の矢印は T19a、空の方位帯は T19b で作る。

## 目的地の入力（大きい地図の中で行う）

- 大きい地図の円の**上の端の内側**に `目的地` を出す（14dp、`#E0F7FF`、不透明度は大きい地図と同じ）。案内中は `ナビ終了` に変わる。下の端の `3D` / `2D`（T16）と同じく、文字の周りに視角 3° 四方程度の当たり判定を取る
- `目的地` をつまむと音声入力を始める
  - 初回は `RECORD_AUDIO` の権限を求める。拒否されたら `マイクの権限がありません` を 3 秒出して地図に戻る
  - 聞いている間は、地図の不透明度を 30% に下げ、円の中央に `話してください`（16dp、`#E0F7FF`）、その下に途中の認識結果（14dp、`#9FE1CB`）を出す。最長 8 秒
  - 認識は `SpeechRecognizer`（日本語 `ja-JP`）。使えない端末では `音声入力が使えません` を 3 秒出して地図に戻る
  - 認識できたら T18a の検索に渡し、`検索中…` を出す
- 候補（最大 3 件）を円の中に行で並べる。1行目に名前（16dp、`#E0F7FF`）、2行目に距離と短い住所（14dp、`#9FE1CB`。例 `450m ・ 渋谷区神南`）。最後に `やめる` の行。行をつまむと、その候補で T18a の経路の取得を始め（`経路を取得中…`）、取れたら案内を始めて地図に戻る
- エラー（通信できない、結果なし、1日の上限、キーや権限のエラー）は、内容に合う短い文（例 `通信できません`、`見つかりませんでした`、`今日の検索の上限です`）を 3 秒出して地図に戻る
- `ナビ終了` をつまむと `もう一度でナビ終了` に変わり、3 秒以内にもう一度つまむとナビをやめる
- **大きい地図の開閉の規則（UI.md §9）はそのまま。** 歩行中は 10 秒、停止中は 30 秒で閉じ、高速移動ですぐ閉じる。入力の途中で閉じたら入力をやめる（検索中なら結果を捨てる。経路の取得中なら、取れても案内を始めない）。入力の操作で自動で閉じる時刻を延ばさない

## 案内中の表示

- **右クラスタ、ミニマップの円の上**に2行で出す。中身は左揃えではなく、ミニマップの中心（右22°）に揃える。内側の端は右16°より外側に保つ
  - 1行目（16dp、`#E0F7FF`）: 次の曲がり角。`30m先 右` の形
    - 距離: 100m 未満は 5m 単位、1km 未満は 10m 単位、1km 以上は小数1桁の km（`1.2km先`）
    - 向き: 左 → `左`、右 → `右`、左斜め・右斜め → `左斜め`・`右斜め`、大きく曲がる → `左に大きく`・`右に大きく`、U ターン → `Uターン`、直進 → `直進`。分類できないときは `navigationInstruction.instructions` を短く切って出す
    - 曲がり角まで 10m 以内は `まもなく 右`
  - 2行目（14dp、`#9FE1CB`）: `残り 1.2km・15分`（距離は UI.md §4 の距離の書き方、時間は分単位の切り上げ）
  - 取り直し中は2行目を `経路を取り直し中…` にする
  - 到着したら1行目を `到着しました`、2行目を空にし、T18a の到着の状態（10 秒）が終わったら消す
  - 測位なしの間は2行とも `#888780`。通信できないときは2行目を `通信できません`（`#888780`）にし、最後の案内を残す
  - ミニマップの大きさ（歩行中 8°、停止中 12°）が変わると、2行の位置も約 300ms で滑らかに動く
- 高速移動中は、ほかの表示と同じくすべて消す
- 案内中も左クラスタはそのまま（変えない）

## 地図の経路

- ミニマップと大きい地図（2D と 3D）に、残りの経路の線を出す。色 `#7FDBFF`、不透明度 60%、太さはミニマップで 3px、大きい地図で 4px 程度。通り過ぎた部分は出さない
- 目的地に小さな円（`#7FDBFF`、線だけ）、次の曲がり角に小さな点を出す
- 測位なしの間は経路の線を 30% にする

## つなぎ込みと自己診断

- T18a の状態の流れと操作を HUD につなぐ。既存の状態の作り方（`HudVisualSpec` など）とタップの仕組み（`HudTarget`、`hudClick`）に合わせる
- デバッグ用の `NAV` ブロードキャストの合成の経路（`--es scenario synthetic`）と、既存の `REPLAY` の合成ルートで、案内の表示が実機でも再現できるようにする
- 自己診断のログ（例: `AuraNav`）に、表示した案内の文字列と状態を出す（座標、施設名、認識した文は出さない）。`scripts/device-check.sh` に `--only nav` を足す（`bash -n` で文法だけ確かめる）

## 確認手順

1. `./gradlew test assembleDebug` が通る（JDK 21）
2. 単体テスト: 距離の丸め、向きの文字列、`まもなく`、残りの時間の切り上げ
3. Robolectric の表示テスト（音声認識と検索は偽物に差し替える）
   - `目的地` → 聞いている表示 → 候補 3 件 → 候補を選ぶ → 案内が始まり、右クラスタに2行が出る
   - 権限の拒否、音声認識が使えない、結果なし、通信できない、1日の上限のそれぞれで、決めた文が出て地図に戻る
   - 入力の途中で大きい地図が自動で閉じたら、入力が止まり、後から結果が来ても案内が始まらない
   - 入力の操作で自動で閉じる時刻が変わらない
   - `ナビ終了` を2回（3 秒以内）でやめる。1回だけでは続く
   - 案内中に高速移動になったら、すぐに `高速移動中のため非表示` だけになる
   - 測位なしで灰色、取り直し中、到着（10 秒で消える）の表示
   - 右クラスタの2行の内側の端が右16°より外側にある（`HudPlacementTest` に追加）
   - ミニマップと大きい地図に経路の線と目的地の円が出る
4. `bash -n scripts/device-check.sh` が通る
5. 既存のテストがすべて通る
6. **実機（adb）は使わない。実際の API も呼ばない**
