# T32: 曲がり角の矢印と目的地の印を、立てた看板として太く明るい線で描く（2026-11-24 室内の確認）

まず [README.md](README.md) の共通ルールを読むこと。T1〜T31 は main に入っている。**安全ルールは [PLAN.md](../PLAN.md) §2.5「空間に置く印」（必読、オーケストレーターが更新済み）**、見た目は [UI.md](../UI.md) §11「空間に置く印」（更新済み）。**どちらも変更しない。**

## 背景

デバッグの `--es mode markpreview`（下記）で、T30 の量子表現の矢印とピンをユーザーに見てもらった。

- 「レトロ感が抜けていない。ベタな色で、PS1 のような古い荒いポリゴンの色合い」。六角形の点を単色で塗り、にじみも単色の段で重ねているため
- 「矢印が斜めになっていて、向きが分からない」。寝かせた矢印を 30° 起こしているので、20m 先から見ると斜めの細い形になる
- HUD の量子演出も屋外では見えにくい、とのこと。ユーザーの判断で、**見えやすさを優先**し、HUD とは色と線の描き方でそろえる

## 決定事項

### 1. 描き方を、立てたパネルに変える

- 曲がり角の矢印と目的地の印（柱とピン）を、`MeshEntity` の点ではなく、信号の柱（`SignalTotemPanel`）と同じく `PanelEntity` に `View` の `Canvas` で描く（アンチエイリアスあり）。親は今までどおり近くのアンカーの `AnchorSpace`
- パネルは**いつも見る人の方を向く**。鉛直の軸のまわりだけ回し（傾けない）、目の位置の方へ向ける。向きの更新は今の更新の頻度（最大 10 Hz、フェード中 30 Hz）の中で行う
- 絵は、形・大きさ・近いかどうかが変わったときだけ描き直す。出る・消えるのフェードは、描き直しではなくエンティティの不透明度で行う
- パネルの画素数は長辺 1024 以下にし、メートルでの大きさは別に決める（遠くの大きな印でも画素数を増やさない）
- 使わなくなった `SpatialMarkMesh` などの点の描画のコードは消してよい。資源の片付けは T30 の決まり（アプリ側で SceneCore の資源を `close()` しない。終了時は SceneCore に任せる。一時停止では隠すだけ）を守る

### 2. 曲がり角の矢印

- 置き場所: 次の曲がり角の位置。**矢印の下端**を目線の 0.6m 上（`EYE_HEIGHT_METERS + 0.6`）に置く。下端がいつも目線より上になるので、仰角で切り取る処理は要らない
- 形: 折れた矢印。下から上へ伸びる軸があり、上で曲がる向きに折れて、先に矢じりがある（右折なら `↱`）。折れる角度は「曲がった先の向き（`outgoingBearing`）− 自分から曲がり角を見た向き」。±20° 未満はまっすぐ上の矢印、±150° を超えたら U ターンの矢印（上で折り返して下を向く）。右に曲がるときは右へ、左に曲がるときは左へ折れる
- 大きさ: 矢印全体の幅は視角 5° 以上（遠いほど大きく）。曲がり角から 10m 以内では、幅を視角 8° までに抑え、不透明度を 50% にする（T30 の規則のまま）
- 曲がり角を過ぎる（次のステップに進む）まで消さない（T30 のまま）

### 3. 目的地の柱とピン

- 目的地の上空に、見る人の方を向く縦の光の線（地上 8m〜40m）と、上端のピンを描く。ピンは T22 のボタンのピン（`BigMapButton.kt` の `drawButtonIcon` の `目的地`: 丸い頭と接線で先端に向かう輪郭、頭の中心の小さな点）と同じ形
- 縦の線は下ほど薄くする（上端 100%、下端 40% 程度）
- 仰角 5° 以上の部分だけを描く規則はそのまま。パネルの中で、仰角 5° より下に当たる部分を切り取って描かない
- ピンの幅は視角 2.5° 以上、縦の線の太さは視角 0.4° 以上
- 出す条件（目的地から 150m 以内）はそのまま

### 4. 線の描き方（UI.md §11）

- 線は 3 層で描く: 芯は `#E0F7FF`（不透明度 100% まで）、その外側を `#7FDBFF` で縁取り、まわりにやわらかいにじみ（不透明度 30% 以下）。にじみは段がつかないように、なめらかに消える（例: `BlurMaskFilter` や、太さと不透明度を少しずつ変えた線を重ねる）。線の端と角は丸める
- 見かけの線の太さ（芯と縁取り）は視角 0.4° 以上
- 面は塗らない。点滅も流れる動きも付けない
- 信号の柱（T24）は変えない

### 5. デバッグの確認用の起動（オーケストレーターが追加済み）

`MainActivity` の `--es mode markpreview`（`diagnostics/MarkPreview.kt`）は、偽の現在地（`--es fakeState stopped`）の北 `distance` m（`--ef distance`、既定 20m）に右折の曲がり角を、その東 15m に目的地を置いた案内を作る。北は、デバッグの北の上書き（`io.github.yamichi77.aurawalkinfo.SETTINGS` の `north_offset 0`）で、起動したときに顔を向けていた方向になる。

- `--es turn` で曲がる向きを選べるようにする: `right`（既定）、`left`、`straight`、`uturn`、`slight_right`（右に 45°）。曲がり角の先の目的地の位置も、その向きに合わせる

## 確認手順

1. `./gradlew test assembleDebug` が通る（JDK 21）
2. 単体テスト
