# T8: 頭を速く動かしている間は HUD を消す（2026-11-23 ユーザー承認）

まず [README.md](README.md) の共通ルールを読むこと。T1〜T6 は完了して main に入っている。

## 背景（装着しての実機確認の結果）

- 頭を止めているときの配置は正確（左クラスタ 左22.0°・下8.0°、1.500m、パネルは頭を向いている）
- **頭を動かしている間、`FollowMode.tight` でも HUD が最大約5°遅れる。** 右クラスタの内側の端が一瞬 右11.8° まで来て、中央クリアゾーン（±15°）に約3°入った（`build/device-check/20261122-235905/log.txt` の `AuraPlacement`）
- 頭を止めていても ±1° 程度の揺れがある
- ユーザーの感想: 「ほぼぴったり。ちょっと酔いやすそう」
- パックのタッチパッドのタップは、アプリに一切届かなかった（`AuraInput` に何も出ない）

これを受けて、ユーザーが「頭を振っている間は HUD を消す」を承認した。

## 作るもの

### 1. 仕様書の更新（ユーザー承認済みの変更。文言はこのとおりにする）

- `docs/UI.md` §5 の表の下の箇条書きの先頭に、次の項目を足す

  > - **頭の回転中は HUD を消す（2026-11-23 ユーザー承認）:** 頭の角速度が 30°/秒を超えたら、左右クラスタ（高速移動中の表示と初回の注意文も含む）を約100ms で消す。15°/秒未満が 0.3 秒続いたら約300ms で戻す。どの状態よりも優先する。理由: 頭を動かした瞬間に HUD が追従に遅れて中央クリアゾーンに入るのを防ぐため（実機で最大約5°の遅れを確認）
- `docs/PLAN.md` §2.4 の表に1行足す: 状態「頭の回転中」、判定「頭の角速度 > 30°/秒（15°/秒未満が 0.3 秒続いたら解除）」、表示「HUD をすべて消す（他の状態より優先）」
- `docs/device-capabilities.md` に記録する: 追従の遅れ（頭の回転中に最大約5°、静止時は ±1° 程度）、タッチパッドのタップがアプリに届かないこと（Full Space の HUD では入力を受け取れない。システムのポインター操作になっていると推測されるが未確認、と書く）

### 2. 頭の回転の検出（`safety/HeadMotionGate.kt` など）

- 頭の姿勢は T4 の配置の自己診断と同じ取り方（ARCore for Jetpack XR の `ArDevice` の pose）で、フレームごとか 30Hz 以上で読む
- 角速度は、連続する2つの姿勢の回転の差（クォータニオンのなす角）÷ 時間。yaw・pitch・roll をまとめた大きさでよい。ノイズで切り替わらないよう、直近 100ms 程度の平均にする
- 判定: 30°/秒を超えたら「回転中」。15°/秒未満が 0.3 秒続いたら「回転中」を解除（ヒステリシス）
- 閾値は1か所の定数にまとめる
- 頭の姿勢が取れない（トラッキングしていない）ときは「回転中ではない」とみなす（今までどおり表示）。そのことを logcat に出す
- 判定ロジックは純粋な Kotlin にして、単体テストを書く（静止 → 振る → 止める、ゆっくり回す（10°/秒）では消えない、閾値付近でばたつかない、など）

### 3. 表示への反映

- 「回転中」の間は、HUD のすべてのパネル（左クラスタ、右クラスタ、高速移動中の表示、初回の注意文）の不透明度を 0 にする。消すときは約100ms、戻すときは約300ms
- 角度ガイド（デバッグ用）は消さない（配置の確認に使うため）
- 初回の注意文の15秒のタイマーは、回転中も進めてよい
- 状態ごとの見た目の仕様（`hudVisualSpecFor`）とは別のレイヤーで掛ける（高速移動の非表示などの既存の判定は変えない）
- デバッグビルドでは、回転中かどうかが変わるたびに logcat（タグ `AuraHeadMotion`）へ `HIDE speed=..` / `SHOW speed=..` を出す。1秒ごとに現在の角速度も出す

### 4. 配置の自己診断の判定を直す

- 頭が静止しているとき（角速度 5°/秒未満）のサンプルだけで判定する
- 中心: 静止サンプルの中央値が 左22°±1°・下8°±1°（右クラスタも同様）
- 内側の端: 中央値が 16°より外側、かつ静止サンプルすべてで 15°より外側（クリアゾーンに入らない）
- 追従（follow）の判定は、「頭の回転中は HUD が消えていること」に置き換える: 回転中（30°/秒超）のサンプルで HUD の不透明度が 0 になっているか

### 5. 実機確認スクリプトの改善（`scripts/device-check.sh`）

- 今回、装着した直後と途中で adb が切れて項目が失敗した（`no devices/emulators found`）。adb のコマンドが失敗したら `adb wait-for-device` で最大20秒待って1回だけやり直す共通関数を作り、使う
- 頭の回転の項目を足す: 「頭を左右に2〜3回、普通の速さで振ってください（10秒）」と表示して待ち、`AuraHeadMotion` に `HIDE` と `SHOW` が1回以上ずつ出たら `PASS`。そのときの最大角速度も記録する
- `--only <項目名>` で一部の項目だけを走らせられるようにする（例: `--only placement,headmotion,map-replay`）。装着中の確認を短くするため

## 確認手順

1. `./gradlew test assembleDebug` が通る（JDK 21）
2. 実機は非装着なので、`bash scripts/device-check.sh --preview` で、既存の項目が壊れていないことと、新しい項目が「非装着」扱いで正しく止まる・スキップされることを確かめる
3. 装着しての確認はオーケストレーターが行う。最終報告に、装着中に走らせるコマンド（`--only` を使った短いもの）を書く
