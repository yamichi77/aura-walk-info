# T34b: 案内の始めに残った一度だけの止まりを減らす（2026-11-25 issue #1 の続き）

まず [README.md](README.md) の共通ルールを読むこと。T1〜T34 は main に入っている。**UI.md と PLAN.md は変更しない**（見た目・配置・閾値・状態ごとの表示は今のまま）。測り方と T34 の結果は [device-capabilities.md](../device-capabilities.md) の「案内中のカクつき」。

## 背景（オーケストレーターの実機の測定。T34 の版）

T34 で案内中ずっと続くカクつきは減った。案内1回につき一度だけの止まりが2つ残っている（AURA は 72Hz、1フレーム 13.9ms）。

1. **空の方位帯が初めて出る瞬間に 150ms と 54ms（続けて2フレーム）。** 1フレーム目は `Compose:recompose` 66ms と `traversal` 71ms。traversal の中に `Compose:initializeView` が4回（方位帯の4枠の `SpatialPanel` を同じフレームで作っている）。2フレーム目は新しいパネルの `relayoutWindow` が続く。修正前は 118ms だったので、T34 で長くなった
2. **「開始」をつまんだ直後に 82ms。** `Recomposer:recompose` 45ms（うち1回の `Compose:recompose` が 19ms）と `traversal` 37ms。traversal の中に `Compose:initializeView` が1回（右の案内パネルを作っている。大きい地図を開いているので、まだ見えない）と、丸いボタンのパネルの描き直しが6回（各 3ms 前後）

## 決定事項

### 1. あとで出すパネルを先に作っておく

- 空の方位帯の4枠と右の案内パネル（`SpatialNavGuidance`）は、使う時点で作らない。HUD を出したあと、起動時の演出が終わってフレームがなめらかに流れ始めてから（`QuantumFrameSettle` と同じ考え方）、**1フレームに1枚まで**作って隠しておく。隠している間は見えず、当たり判定を持たない（T33・T34 と同じ）
- 先に作り終わる前に必要になった場合（起動直後に案内を始めたなど）は、そのとき足りない分を1フレームに1枚ずつ作る。表示が遅れる長さを最終報告に書く
- 右の案内パネルは、矢印あり・なしで幅と位置が変わる（`HudPlacement.navWidthMeters`・`navPose`）。先に作るために大きさを固定する場合は、両方を含む大きさにして、中の文字と矢印が今と同じ位置に見えるようにする。パネルの画素数を途中で変えない
- 高速移動で HUD を隠すときや、案内をやめたときにパネルを壊さない（隠すだけ）。アプリを閉じるときの後片付けは今どおり

### 2. 「開始」のフレームの仕事を減らす

- 「開始」をつまんだフレームで、パネルを作ったり、まだ見えない中身を組み立てたりしない（大きい地図を開いている間は右の案内は見えないので、中身の組み立ては次のフレーム以降でよい。大きい地図が閉じるまでに間に合えばよい）
- 残りの重い処理を特定するために、`android.os.Trace.beginSection`/`endSection`（または既に使えるなら `androidx.tracing.trace`）で、HUD の主な部分（左のクラスタ、共有の地図、大きい地図のボタン、目的地の入力の表示、右の案内、方位帯）を区切る。トレースを取っていないときの負担はほぼない。区間名に座標や地名を入れない
- そのうえで、「開始」のフレームで同時に起きる変更（候補・ルート全体の表示から案内への切り替え、ボタンの入れ替え、地図のカメラ）のうち、見た目を変えずに次のフレーム以降へずらせるものがあれば分ける。何をずらしたかと理由を最終報告に書く

### 3. 目標

- 実機で、方位帯が初めて出る瞬間と「開始」の直後の、いちばん長いフレームの間隔を **42ms（3フレーム）以下**にする。実機での測定はオーケストレーターが行う
- 案内中ずっと続く部分（T34 の結果）を悪くしない

## 確認手順

1. `./gradlew test assembleDebug` が通る（JDK 21）
2. Robolectric の表示テスト
   - HUD を出してしばらくすると、方位帯の4枠と右の案内パネルが作られて隠れている。そのあと案内を始めて方位帯を出しても、パネルが新しく作られない（作った回数を数えられる形にする）
   - 先に作り終わる前に方位帯が必要になったとき、1フレームに1枚ずつ作られ、最後には今と同じ位置に出る
   - 右の案内パネルの文字と矢印の位置が今と同じ（矢印あり・なしの両方）。大きい地図を開いている間は見えない
   - 今の方位帯・案内・大きい地図・空間の印のテストが通る（合わせて直す）
3. **実機（adb）は使わない。** main のワークツリーには触らない

## 受け入れ条件

- 上の確認がすべて通る
- UI.md と PLAN.md を変更していない
