# T6: 安全機能と合成ルートの再生

まず [README.md](README.md) の共通ルールを読むこと。T1〜T4 は完了している。T5（ミニマップ）が別の worktree で同時に進んでいる。

## 目的

PLAN.md §2.4 の安全機能を仕上げ、**屋外を歩かずに実機上で状態の切替を再現して確かめられる**ようにする。
**高速移動時の非表示と中央クリアゾーンは、どんな操作でも上書きできないようにする。**

## 並行作業との分担

T5 が触るのは `ui/hud/MiniMapPanel.kt`（新規）、地図スタイルの JSON、`HudScene` の中の右クラスタを呼ぶ1か所だけ。このタスクでは右クラスタの中身と地図には触らない。

## 作るもの

### 1. 合成ルートの再生（デバッグビルドのみ）

- `--es replay <シナリオ>` で起動すると、本物の位置の代わりに合成した位置を `LocationRepository` に流す（`AppContainer` で差し替える）。`--ef replaySpeed <倍率>`（既定 1.0）で早送りできる
  - T3 の `FakeLocationRepository` と合成データの生成関数（`SyntheticLocations.kt`）は test ソースセットにある。再生とテストの両方で使えるよう、main ソースセットの `diagnostics/replay/` などに移し、テストからもそれを使う
  - 早送りするときは、`LocationSample` の時刻と `Clock` の両方を同じ倍率で進める（測位なしのタイムアウト判定がずれないように）
- 起点は公共の場所（例: 東京駅丸の内駅前広場付近）にする。実在の歩行ログは使わない
- シナリオ（1秒に1点。精度は通常 5m 程度で少し揺らす）

| 名前 | 内容 |
|---|---|
| `walk_stop` | 1.3 m/s で60秒歩く → 30秒立ち止まる（精度 5〜15m の揺らぎ） → 1.3 m/s で60秒、途中で一度 90° 曲がる |
| `fast` | 1.3 m/s で30秒歩く → 6 m/s で30秒 → 1.3 m/s で30秒 |
| `nofix` | 1.3 m/s で30秒歩く → 15秒間位置が来ない → 精度 40m の点が10秒 → 1.3 m/s で30秒 |

- 再生中は、状態の変化と1秒ごとの値を logcat（タグ `AuraSession`）に出す: 経過秒、状態、3秒平均の速度、精度、距離、歩行時間、クラスタを表示しているか。**緯度経度と住所は出さない**
- 住所は再生中は Geocoder を呼ばずに、ダミーの住所（例: `千代田区丸の内1丁目`）を返す

### 2. 状態の切替のエンドツーエンドテスト（JVM）

- 上の3つのシナリオを、`FakeLocationRepository` → `WalkSessionRepository` → T4 の `hudVisualSpecFor`（状態 → 見た目の仕様）まで通して、仮想時間で流すテストを書く
- 確かめること
  - `fast`: 6 m/s になってから 5秒（±1秒）でクラスタが非表示になり、`高速移動中のため非表示` が出る。6 m/s の区間の距離と歩行時間は増えない。歩行に戻って5秒後にクラスタが戻る
  - `walk_stop`: 立ち止まって5秒で停止中になり、停止中は距離も歩行時間も増えない。補助行と住所2行が出る
  - `nofix`: 位置が10秒来ないと測位なしになり、`GPS 測位中…`。精度 40m の間も測位なし。その間、距離と歩行時間は増えない

### 3. 初回起動時の注意文（PLAN.md §2.4）

- 文言: 「徒歩専用。自転車・運転中は使用不可。横断歩道や駅のホームでは周囲を優先」
- 表示位置: **左クラスタの位置**（UI.md に位置の定めが無いので、オーケストレーターが決めた。中央クリアゾーンには出さない）。14dp、`#E0F7FF`、複数行でよい。表示中は左クラスタの数値の代わりに出す
- 初回起動時だけ出す。15秒たつか、タッチパッドの操作（下記）があったら消して、「表示済み」を保存する（T3 の `SafetyNotice`）
- デバッグビルドでは `--ez resetNotice true` でもう一度出せるようにする
- Compose UI テストで、初回は出る・2回目は出ない・15秒で消える、を確かめる

### 4. タッチパッドでの表示・非表示の切替（任意）

- T2 の結果（`docs/device-capabilities.md`）を見て、パックのタッチパッドのタップで届きそうなイベント（キーイベントの決定キー類、または source がタッチパッド / マウスのクリック）を受けたら、HUD の表示・非表示を切り替える。連打で何度も切り替わらないよう 500ms 程度の間引きを入れる
- **高速移動中の非表示は、タッチパッドの操作で表示に戻せないこと。** 単体テストで確かめる
- 実際のタップで何が届くかはまだ分かっていない。受け付けたイベントの種類を logcat（タグ `AuraInput`）に出し、最後にユーザーに確かめてもらう

### 5. フィールドログ（HANDOFF.md §6）

散歩の後に閾値を調整するための記録。

- デバッグビルドで常に記録する。保存先はアプリの files ディレクトリの `fieldlog/` 配下に、セッションごとに1つの CSV
- 1秒に1行: 経過秒、状態、3秒平均の速度、精度、その秒に足した距離、採用した点か捨てた点か（と捨てた理由）、クラスタを表示しているか、測位プロバイダ
- **緯度経度と住所は記録しない**
- 取り出し方: `adb exec-out run-as io.github.yamichi77.aurawalkinfo ...` で取り出すコマンドを `docs/field-test.md`（新規）の冒頭に書く
- リポジトリの `.gitignore` に、取り出したログの置き場所（例: `fieldlogs/`）を追加する

## 確認手順（すべて自動で行う）

1. `./gradlew test` と `./gradlew assembleDebug` が通る
2. 実機で3つのシナリオを `--ef replaySpeed 4` で再生し、`adb logcat -s AuraSession` の出力が上の「確かめること」と一致することを確かめる。結果の要約（状態が切り替わった秒数など）を最終報告に書く
3. 再生中に T2 のアプリ内キャプチャで左クラスタを撮り、高速移動中に数値が消えていることを画像で確かめる
4. `--ez resetNotice true` で注意文が出て、15秒で消えることをキャプチャか logcat で確かめる
5. `fast` の再生中に `adb shell input` でタッチパッド相当のイベントを注入しても、表示に戻らないことを確かめる
6. フィールドログが作られ、緯度経度が含まれていないことを確かめる（取り出した CSV を `build/` の下に置いて中身を見る）

## 受け入れ条件

- 状態の切替（歩行中 / 停止中 / 高速移動 / 測位なし）を単体テストと実機の再生の両方で確かめた
- 高速移動中の非表示は、タッチパッドの操作で解除されない
- 初回の注意文が中央クリアゾーンの外に出て、2回目以降は出ない
- フィールドログに位置情報が含まれない
