# T19b: 空の方位帯（2026-11-23 ユーザー承認・見た目は暫定）

まず [README.md](README.md) の共通ルールを読むこと。T1〜T19a は main に入っている。追加機能の全体は [PLAN.md](../PLAN.md) §9、**安全ルールは §2.5（必読）**、表示の原則は [UI.md](../UI.md) §11。

## 目的

視界の上端（上14°〜19°）の帯に、現実の方位に合わせて、ナビの次の曲がり角・目的地と、信号機の交差点の方向を小さな印で出す。高さは頭に固定し、水平の位置だけを現実の方位に合わせる。見た目は暫定で、受け入れでユーザーに確認する。**UI.md と PLAN.md は変更しない**。

## 出すもの

帯の中に、次の印だけを置く。**帯全体に伸びる線（方位の目盛りや水平線）は描かない。**

| 印 | 形 | 出す条件 |
|---|---|---|
| 次の曲がり角 | 下向きの小さな山形（▽の輪郭、幅 1.2° 程度）を上17.5°に、その下（上15°）に距離（14dp、例 `120m`。書き方は T18b の距離の丸めと同じ） | 案内中 |
| 目的地 | 小さな円の輪郭（直径 1° 程度）を上17.5°に | 案内中で、目的地が次の曲がり角と 3° 以上離れて見えるとき |
| 信号機の交差点 | 小さな円の輪郭の下に、灯器ごとの小さな点（T17b と同じ色と並べ方）を上17.5°に | T17a の判定が交差点を返しているとき |

- 色は `#7FDBFF`（信号の点は T17b の色）。不透明度は 50% 以下。面は塗らない
- 印の水平の位置: `印の方位 − 頭の向き（北基準）` を、左右の角度（右が正）として `HudPlacement` で置く。方位は T18a（曲がり角・目的地）と T17a（交差点）が出す、今の位置からの方位（北 0°、時計回り）
- 次の曲がり角の印が視界の外（左右 27° より外）にあるときは、帯の端（左28° または 右28°）に `‹` または `›` の小さな山形を出す。目的地と信号機の印には端の山形を出さない
- 帯の外（上14° より下、上19° より上）には何も描かない

## 頭の向き（北基準）

- T15 の `HeadingEstimator` のオフセットと、ARCore の頭の yaw から求める
- 頭の向きは、ちらつかないよう時定数 150ms 程度でなめらかにする（境目の 0°/360° に注意）
- 印の位置の更新は最大 15 Hz。HUD の全体を作り直さないよう、帯の状態を分ける

## 消す条件（PLAN.md §2.5）

次のどれかのとき、帯の印をすべて消す。

- 高速移動中
- ARCore の追跡が TRACKING でない
- 北の向きの推定が無い、または不確かさが 15° を超える
- 設定で帯がオフ
- 案内中でなく、信号機の判定も交差点を返していない

消えるときと出るときは約 300ms のフェード。ただし高速移動ではすぐに消す。

## 設定

- 帯のオン・オフを端末に覚えておく（T16 で作った設定の保存場所を使う）。初期値はオン
- 今回は HUD の中に切り替えの操作を置かない（受け入れでユーザーと決める）。デバッグ用のブロードキャスト（例: `io.github.yamichi77.aurawalkinfo.SETTINGS --ez sky_band false`）で切り替えられるようにする

## 自己診断

- 配置の自己診断（`AuraPlacement`）に、帯の印の上下の角度が 14°〜19° に収まっていることの判定を足す
- `AuraSky` などのログに、帯の状態（出す / 消す とその理由）、頭の向き、推定の不確かさ、各印の左右の角度を出す（座標は出さない）
- デバッグ用に、北の向きの推定を固定値で上書きできるようにする（例: `SETTINGS --ef north_offset 0 --ef north_uncertainty 5`）。実機で歩かずに帯の表示を確かめるため
- `scripts/device-check.sh` に `--only skyband` を足す（推定の上書き、合成の経路、`PICS_REPLAY` を組み合わせて、印が出ることと消える条件をログで確かめる）。`bash -n` で文法だけ確かめる

## 確認手順

1. `./gradlew test assembleDebug` が通る（JDK 21）
2. 単体テスト
   - 印の左右の角度: 方位と頭の向きの差（境目の 0°/360° をまたぐ場合を含む）
   - 視界の外の判定（27° の境目）と端の山形の左右
   - 目的地の印を出す条件（曲がり角と 3° の境目）
   - なめらかにする処理が境目で正しく回る
   - 消す条件のそれぞれ
3. Robolectric の表示テスト
   - 案内中で推定があるとき、曲がり角の印と距離が帯に出る
   - 信号機の判定が交差点を返すと、交差点の印が出る
   - 高速移動・追跡なし・推定なし・不確かさ 15° 超え・設定オフで消える。高速移動ではフェードせずすぐに消える
   - 印がすべて上14°〜19° の中にある（`HudPlacementTest` に追加）
   - 帯全体に伸びる線が描かれていない
4. `bash -n scripts/device-check.sh` が通る
5. 既存のテストがすべて通る
6. **実機（adb）は使わない（インストールもしない）**
