# T33: ミニマップと大きい地図で1枚の地図を共有し、開くときは中央へ動いて広がる（2026-11-25 ユーザー判断）

まず [README.md](README.md) の共通ルールを読むこと。T1〜T32 は main に入っている。仕様は [UI.md](../UI.md) §9「大きい地図」の「開く・閉じる」と §10 の表（オーケストレーターが更新済み。**UI.md は変更しない**）。

## 背景

- ミニマップ（右下の円）と大きい地図は、別々の `GoogleMap`（`MapView`）を持っている。大きい地図は開くたびに作り、閉じると捨てている（`HudScene.kt` の `SpatialHudPanels`、`MiniMapPanel.kt` の `ClickableMap`）
- 開くたびに、地図・右側の丸いボタン5つ・外側のタップを受けるパネルを作るので、メイン処理が約 0.35 秒（起動して1回目は約 0.45 秒）止まる（`Choreographer: Skipped 33 frames`）。量子演出がカクついて見えた
- その場しのぎとして、開く演出をフレームが流れ始めるまで待たせた（`QuantumHud.kt` の `QuantumFrameSettle`。待ちは約 130ms、演出中の最長フレーム間隔は 30〜44ms）
- ユーザーの判断: 地図を1枚にして共有し、開くときはミニマップの円が中央へ動きながら広がる見せ方にする

## 決定事項

### 1. 地図を1枚にする

- ミニマップと大きい地図で、同じ1つの `GoogleMap`（`MapView`）を使う。**大きい地図を開く・閉じるときに地図を作り直さない**
- できれば、高速移動の表示の間も地図を捨てずに隠しておき、戻ったときに作り直さない（作り直しが避けられない場合は、その理由を最終報告に書く）
- 地図の操作（つまんで動かす、長押しで目的地、`＋`/`－`/`現在地`）は、大きい地図のときだけ効く。ミニマップのときのタップは今までどおり大きい地図を開く（`HudTarget.MAP`）。大きい地図のときは `HudTarget.BIGMAP`
- ミニマップに戻ったら、カメラ（中心・拡大率・傾き）とスタイルはミニマップの設定に戻す（大きい地図で動かした場所は、開き直すと現在地に戻る。今までどおり）
- 地図の中身（経路線、ルート全体の表示、候補のときの不透明度など）は今までどおり

### 2. 中央へ動いて広がる（UI.md §9）

- 開く: ミニマップの円が、約 **350ms**（ease-in-out）で、大きい地図の位置（正面・下4°、`HudPlacement` の大きい地図の姿勢）へ動きながら直径 28° に広がる。閉じる: 逆に、ミニマップの位置と直径（歩行中 8°・停止中 12°）へ戻りながら縮む。タップで閉じるときも自動で閉じるときも同じ
- 動いている間も地図の中身は見えたまま。途中で消えたり、黒い枠や空の地図が見えたりしない
- 不透明度（ミニマップの値 ↔ 大きい地図の歩行中 70%・停止中 100%）と円の枠も、動きに合わせて変える
- 拡大率と傾き: 動き始めから着くまでの間に、ミニマップのカメラから大きい地図のカメラ（2D はズーム 16.5、3D は 60° 傾けてズーム 18）へなめらかに変える。地図のスタイル（大きい地図では名前を出す、3D のスタイル）の切り替えは、見た目が跳ばない時点で行う
- **高速移動では動かさずに、すぐに閉じる**（今までどおり。ミニマップも高速移動の表示に従う）
- 大きい地図を開いている間は右クラスタ（案内の2行と矢印）を出さない（今までどおり）。閉じ終わってから出す
- 配置の自己診断（`HudPlacementCheck`）の `RIGHT` と `BIGMAP` の測定は、動き終わった姿勢で今までどおり通ること

### 3. 描画の負荷の決まり

- **パネルの画素数を毎フレーム変えない。** 見た目の大きさの変化は、エンティティの拡大縮小（`SubspaceModifier.scale` など）で行う。画素数を変える必要があるなら、開くとき・閉じるときにそれぞれ1回までにする
- 推奨の作り（固定版のソースで確かめて、より良い方法があれば変えてよい。選んだ方法と理由を最終報告に書く）:
  - 開くとき: 最初に1回だけパネルを大きい地図の画素数にし、同時にエンティティを「ミニマップの見かけの直径 ÷ 28°」に縮め、カメラの拡大率を `ミニマップのズーム + log2(大きい地図の画素数 ÷ ミニマップの画素数)` にして、見た目が変わらないようにする。そこから位置・拡大縮小・カメラを一緒に動かす
  - 閉じるとき: その逆で、着いてから1回だけミニマップの画素数に戻す
- 右側の丸いボタン5つと、外側のタップを受ける透明なパネルは、大きい地図を開くたびに作らないようにする（最初に作って隠しておく、など）。隠している間はタップを受けない。固定版の Compose for XR でできない場合は、その理由を最終報告に書き、作る負荷が少ない方法を選ぶ
- 動きの最中のいちばん長いフレームの間隔、画素数を変えたときにかかった時間を `AuraBigMap` のログに出す（例 `transition=open longestFrameMillis=.. resizeMillis=..`）。座標や地図の中身はログに出さない

### 4. 量子演出（UI.md §10 の表）

- 大きい地図を開くときの「点が集まって円になり、地図がフェードインする」演出はやめる。代わりに、着いた瞬間に円の縁を約 0.2 秒明るく光らせる（今の縁の光と同じ）
- 右側の丸いボタンは、着いてから点が集まって現れ、光点が円の上を1回だけ回る（今の T22・T28 の演出を、着いた時点から始める）。つまんだときの波紋は今までどおり
- 閉じるとき: ボタンはフェードで消え、地図の円が右下へ動きながら縮む。大きい地図の点が散る演出と、ミニマップが点から集まる演出はやめる
- アプリの起動時のミニマップの演出（点から現れる）は今までどおり
- `QuantumFrameSettle` は、大きい地図の演出には要らなくなる。動きの始めに止まりが残るなら、動きの開始を同じ方法で待ってよい（使わないなら消してよい）
- `QuantumEffectsEnabled = false` のときは、ボタンの演出と縁の光を出さない（動いて広がる・縮むのは出す）

### 5. 起動時の演出は、地図を読み込んでから始める（2026-11-25 ユーザー要望で追加）

- 起動直後も、地図を作る処理で量子演出がカクついていた
- **ミニマップ**の起動時の演出（点から現れる）は、地図の読み込みが終わってから始める（`GoogleMap` の `onMapLoaded` など。最長 **2 秒**待ったら、読み込みが終わっていなくても始める）。そのあと、`QuantumFrameSettle` と同じ方法でフレームがなめらかに流れ始めるのを待ってから始める。待っている間は、ミニマップも点も出さない
- **左クラスタ**の起動時の演出は、地図の読み込みは待たず、フレームがなめらかに流れ始めるのだけを待つ（左の表示が遅れすぎないように）
- 位置の権限が無いなど、地図を出さないときは地図を待たない
- 待った時間と、演出中のいちばん長いフレームの間隔を `AuraQuantum` のログに出す（今の大きい地図の演出と同じ形）
- 確認: Robolectric の表示テストで、地図の読み込みが終わるまでミニマップの演出が始まらないこと、2 秒で始まること、左クラスタは地図を待たないこと

### 6. 動いて広がる見せ方をやめ、元の量子演出に戻す（2026-11-25 ユーザー判断で追加。§2 と §4 を置き換える）

実機で見たユーザーの判断で、ミニマップの円が中央へ動いて広がる・縮んで戻る動きはやめる。**地図を1枚で共有することは続ける**（開くときの止まりが 0.35〜0.45 秒から 0.03〜0.04 秒になったため）。UI.md §9 の「開く・閉じる」と §10 の表は、オーケストレーターが元の演出に戻した。

- 開く: ミニマップを消し、地図が見えていない間に、地図を大きい地図の位置・大きさに移し、カメラ（2D はズーム 16.5、3D は 60° 傾けてズーム 18）とスタイルを切り替える。そのうえで、T13・T28 の元の演出をそのまま出す（点が集まって直径 28° の円の輪郭になり、地図がフェードインする。集まりきった瞬間に円の縁を約 0.2 秒光らせる。右側の丸いボタンは今までどおり大きい地図と一緒に点から集まって現れ、光点が1回回る）
- 閉じる: 元の演出（大きい地図の点が外へ散って消え、ボタンもフェードで消える）。消えきったら、地図を見えない状態でミニマップの位置・大きさ・カメラ・スタイルに戻し、ミニマップが点から集まって現れる
- 動き（位置と大きさの補間）のコードは消してよい。地図を作り直さないこと、ボタンと外側のパネルを開くたびに作らないこと、パネルの画素数を毎回変えないこと（§3）は続ける
- 地図を移したりカメラやスタイルを切り替えたりする処理で止まりが出るなら、元の演出を、フレームがなめらかに流れ始めてから始める（`QuantumFrameSettle` と同じ方法）
- `AuraBigMap` の `transition=open|close longestFrameMillis=..` は、演出の間の値として残す
- 確認: 表示テストで、開くとき点が集まって地図がフェードインし（途中で地図が動かない）、閉じるとき点が散ってミニマップが点から現れること。何回開いても地図は1回しか作られないこと。今の T33 のテストのうち動きのテストは、この仕様に合わせて直すか消す

## 確認手順

1. `./gradlew test assembleDebug` が通る（JDK 21）
2. Robolectric の表示テスト
   - 大きい地図を何回開いても閉じても、地図（`MapView`）は1回しか作られない（地図を作る処理を数えられる形にする）
   - 開く: 始め・途中・終わりで、位置と直径がミニマップ → 大きい地図に変わる。終わったら操作（つまむ・長押し・ボタン）が効く。途中で地図が消えない
   - 閉じる（タップ・自動・やめる → 閉じる）: 逆に戻り、終わったらミニマップのタップで再び開ける
   - 高速移動: 動かずにすぐ閉じる。開いている途中で高速移動になっても、すぐ閉じる
   - ボタンは着いてから点が集まって現れ、縁は着いた瞬間に光る。閉じるときボタンはフェードで消える。`QuantumEffectsEnabled = false` でボタンの演出と縁の光なし
   - 候補・ルート全体の表示・3D/2D の切り替えなど、今の大きい地図のテストが通る（合わせて直す）
3. 単体テスト: 動きの補間（ease-in-out、350ms、途中で向きが変わったときの扱い）、拡大率の補正の計算
4. 既存のテストを合わせて直し、すべて通す
5. **実機（adb）は使わない**。main のワークツリーには触らない。実機でのカクつきの測定はオーケストレーターが行う
