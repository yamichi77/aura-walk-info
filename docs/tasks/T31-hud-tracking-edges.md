# T31: 頭の追跡を待たずに HUD を出す。頭を回したときに HUD の端が切れないようにする（2026-11-24 屋外の試用）

まず [README.md](README.md) の共通ルールを読むこと。T1〜T29 は main に入っている。

**並行作業の注意:** T30（空間の印と北の推定とクラッシュ）が別のワークツリーで並行して進む。T30 は `spatial/` と `heading/` を触る。T31 はそれらに触らず、`ui/hud/HudScene.kt`・`HudPlacement.kt`・`settings/HudLayoutConfig.kt` とそのテストを中心に扱う。

## 背景

1. **起動直後に HUD が出ない:** `HudScene` は、頭の追跡が `TrackingState.TRACKING` になるまで HUD のパネルを描かない（`if (tracking || showRotationFallback)`）。トラベルモードがオンで起動すると、追跡が始まるまで数秒かかり（ログでは約 2 秒、`AuraHeadMotion speed=unavailable`）、その間 HUD が何も出ない。ユーザーから「トラベルモードで起動すると何も見えない」との報告があった（トラベルモードの切り替えでアプリが後ろに下げられるのはシステムの動きで、ここでは扱わない）
2. **HUD の端が切れる:** トラベルモードがオフ（6DoF）のとき、頭を回すと HUD が遅れてついてきて、左右のクラスタの外側の端が表示できる範囲（左右約 30°）の外に出て見えなくなる。左クラスタの外側の端は左29°、ミニマップの外側は右28° 付近にある

## 決定事項

### 1. 追跡を待たずに出す

- 頭の追跡がまだ始まっていない、または途切れていても、HUD のパネル（左クラスタ、ミニマップ、案内の2行、大きい地図など頭に追従する表示）は出す。`Subspace(follow = FollowTarget.view(...))` が追跡なしでどう振る舞うか（置き場所が決まらない、など）を、`gradle/libs.versions.toml` のバージョンの Compose for XR のソースで確かめ、出せる形にする
- 追跡が要るもの（配置の自己診断、頭の角速度、空の方位帯、空間の印）は今までどおり追跡を待つ
- 追跡なしで出しているかどうかを `AuraHud` のログに出す

### 2. 頭を回したときの遅れと端

- まず、頭に追従させる方法で遅れを減らせないかを調べる。例: Compose for XR の `FollowMode` の設定、SceneCore で頭（視点）に直接つなげる仕組みがあるか。固定版のライブラリのソースで調べ、遅れが減る方法があれば使う。調べた結果を最終報告に書く
- 遅れが減らせない場合は、**左右のクラスタを内側に寄せて、外側の端に余白を作る。** 外側の端が左右 **26°** を超えないようにする（今は左29°・右28°）。中央クリアゾーンとの間隔（内側の端が左右16° より外）は守る。そのために必要なら、左クラスタの幅（文字の横方向の縮小の上限）とミニマップの直径を調整する。調整した値を最終報告に書く（UI.md の数値の変更はオーケストレーターがユーザーに確認してから行う）
- 大きい地図の右側の丸いボタン（T27・T28）の外側の端も、同じく 26° 以内に収める

## 確認手順

1. `./gradlew test assembleDebug` が通る（JDK 21）
2. 配置のテスト（`HudPlacementTest`）: 左右のクラスタとボタンの外側の端が 26° 以内、内側の端が 16° より外
3. Robolectric の表示テスト: 頭の追跡が無い状態でも、左クラスタとミニマップが出る（追跡の状態を差し替えられる形にする）。空の方位帯と空間の印は出ない
4. 既存のテストを合わせて直し、すべて通す
5. **実機（adb）は使わない**。main のワークツリーには触らない

## 受け入れ条件

- 上の確認がすべて通る
- UI.md と PLAN.md を変更していない
