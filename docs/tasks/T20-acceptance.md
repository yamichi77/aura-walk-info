# T20: 追加機能の受け入れ（AURA の実機で確かめる）

オーケストレーター（Opus）がユーザーと一緒に進める。T14〜T19b が main に入っていることが前提。結果は `docs/device-capabilities.md` と `docs/field-test.md` に書く（**座標・住所・施設名は書かない**）。

## 0. 事前の準備（ユーザー）

- [ ] Google Cloud で **Routes API** と **Places API (New)** を有効にする
- [ ] 今の Maps の API キーの「API の制限」に、Routes API と Places API (New) を加える（アプリの制限はパッケージ名と SHA-1 のまま）
- [ ] 1日の上限: Routes API 300 回、Places API (New) 150 回（アプリ側の上限と同じ値）
- [ ] AURA を充電し、USB で PC につなぐ。散歩ではスマホのテザリングを用意する
- （任意）Geospatial を試す場合は ARCore API の有効化と認証の設定が別に要る。今回の空の方位帯は、GPS とグラスの追跡による推定で動くので必須ではない

## 1. インストール（オーケストレーター）

- `./gradlew assembleDebug`（JDK 21）→ `adb install -r app/build/outputs/apk/debug/app-debug.apk`
- 権限: 起動時に位置・頭の追跡・Bluetooth のスキャンを許可する。マイクは目的地の入力を初めて使うときに許可する

## 2. 室内（グラスをかけて、座ったまま）

| 確認 | 手順 | 見るところ |
|---|---|---|
| 配置と現在時刻 | `bash scripts/device-check.sh --only placement` | 時刻が左クラスタの一番上にあり、中央クリアゾーンにかからない |
| 大きい地図の 3D | `--only map3d` のあと、通常の起動で大きい地図を開き、下の端の `3D` / `2D` をつまむ | 建物が暗い灰色の立体で出る。矢印が円の中心にある。文字をつまみやすい |
| 頭の向きの安定性 | `--only heading`（正面を向いて 60 秒静止） | yaw の変化の幅 |
| 音声認識 | `--only speech`（合図で「東京駅」と話す） | 日本語で認識できるか |
| BLE | `--only ble` | スキャンが動き、周りのアドバタイズの件数が出る |
| 信号の表示（合成） | `--only pics` | 左クラスタの `信号 …` の行、地図の交差点の印、灰色と消える動き |
| ナビの表示（合成） | `--only nav` | 右クラスタの案内の2行、立体の矢印、地図の経路線、到着 |
| 空の方位帯（合成） | `--only skyband` | 上14°〜19° の印、視界の外の端の山形、消える条件 |

- 暫定の見た目（信号の行と印、ナビの2行と矢印、空の方位帯）をユーザーに見てもらい、了承か直したい点を聞く。了承されたら UI.md §11 に書き足す

## 3. 室内（通信あり）: 目的地の入力

- 大きい地図を開き（停止中）、`目的地` をつまんで、近くの施設名を話す → 候補 → 選ぶ → 案内が始まる
- 確かめること: 候補が出るまでの時間、経路の取得、エラーの文（機内モードなどで通信を切って試す）

## 4. 屋外（最初は車の来ない公園などで）

- 近くの目的地を音声で設定し、5〜10 分歩く。まっすぐの区間と、向きの違う区間を含める
- 見るところ: 案内の2行の更新、曲がり角での矢印の向き、空の方位帯の印が現実の方向と合っているか、北の向きの推定が出るまでの時間
- 歩いたあと、フィールドログを取り出して `python scripts/heading-analysis.py <CSV>` を実行し、ARCore の座標系の向き（正面と yaw の符号）が初期値どおりかを確かめる。違っていたら `HeadingAxes` の定数を直す
- 安全な場所で、右を向く・前に進むを試し、空の方位帯の印が逆に動かないかを見る

## 5. 信号機（任意）

- 近くに高度化PICS の交差点があれば、停止中に 30m 以内で `信号 …` の行が出るかを見る（**表示は参考。必ず実際の信号を見て渡る**）
- 無ければ、室内でスマホのアプリ（nRF Connect など）から **Company ID `0xFFFF`** の合成の電文を送って受信を確かめる（デバッグビルドだけが受け付ける）。実物の形式（`0x01CE`）では送らない
  - 種類 2（信号）の例: `00 00 02 01 00 00 DE AD BE EF 11`（交差点 ID `DEADBEEF`、灯器1が赤（下位 4 ビット 1）で残り値 2（上位 4 ビット 1 + 1））
  - 位置（種類 1）は屋内の今の位置に近い値が要るため、合成の再生（`--only pics`）での確認を主とする
