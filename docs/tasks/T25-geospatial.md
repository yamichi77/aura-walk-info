# T25: Geospatial（VPS）で空間の印の位置と北の向きを決める（2026-11-24 ユーザー判断）

まず [README.md](README.md) の共通ルールを読むこと。T1〜T23 は main に入っている。T24（信号の柱）が別のワークツリーで並行して進んでいる。**安全ルールは [PLAN.md](../PLAN.md) §2.5「空間に置く印」（必読）**。

**並行作業の注意:** T24 は信号の柱の描画と、左の信号の行・地図の信号の印の削除を行う。T25 は位置と北の向きの「もと」を差し替える部分だけを扱い、印の描画のコードには最小限しか触らない。

## 目的

T23 の空間の印は、GPS と北の推定（T15）で位置を決めているので、5〜10m ずれたり、測位の更新で跳ねたりする。Geospatial（VPS）が使えるときは、カメラの映像で位置合わせした地球上の姿勢（緯度経度・高さ・向き）を使い、正確に置く。北の向きも VPS から取り、空の方位帯（T19b）と視界の端の矢印（T19a）も正確にする。VPS が使えないときは、今の GPS と北の推定に自動で戻す。

## 決定事項

- **認証は今の Maps の API キーを使う**（ユーザーが Google Cloud で ARCore API を有効にし、キーの「API の制限」に足す）。マニフェストの `<application>` に `<meta-data android:name="com.google.android.ar.API_KEY" android:value="${MAPS_API_KEY}" />` を足し、今の `com.google.android.geo.API_KEY` と同じプレースホルダーでキーを渡す。**キーの値をコードやリポジトリに書かない**（`local.properties` から secrets-gradle-plugin で入る今の仕組みのまま）。設定の詳細は、`gradle/libs.versions.toml` のバージョンのライブラリと公式のセットアップ手順（https://developer.android.com/develop/xr/jetpack-xr-sdk/arcore/geospatial/setup ）で確かめる
- **利用の確認:** VPS はカメラの映像を位置合わせのために Google に送る。初めて VPS を使う前に、左クラスタの位置に短い確認の文（例: `位置合わせのためカメラの映像を Google に送ります。使いますか？`）と `使う` / `使わない` のボタン（T22 の丸いボタンと同じ見た目）を出し、答えを保存する。`使わない` なら VPS を有効にしない（GPS と北の推定のまま）。デバッグ用の `SETTINGS` ブロードキャストで答えを消せるようにする。文言は公式の要件を満たすよう調べて決め、最終報告に書く
- **使う条件:** `Geospatial` の状態が RUNNING で、水平の精度 ≤ 5m かつ向き（yaw）の精度 ≤ 5° のときだけ VPS の値を使う（定数）。それ以外、または追跡が途切れたら、GPS と北の推定（T15・T23）に戻す。切り替わるときに印が跳ねないよう、T23 の滑らかな移動を使う
- **場所ごとの可否:** 起動時と、大きく移動したとき（500m 以上）に `checkVpsAvailability` を呼び、VPS が使えない場所では VPS の状態を待たずに GPS に戻す
- **位置の変換:** T23 の「緯度経度 → 空間の位置」のインターフェースに、VPS 版の実装を足す（Geospatial の姿勢の変換、またはジオスペーシャルのアンカー。どちらを使うかはライブラリを調べて決め、理由を最終報告に書く）
- **北の向き:** VPS が使える間は、VPS の向きから頭の向き（北基準）を求め、空の方位帯と視界の端の矢印に渡す。不確かさには VPS の yaw の精度を使う。使えない間は T15 の推定のまま
- **電池:** VPS は空間の印・空の方位帯・矢印のどれかが出る可能性があるとき（案内中、または信号機の情報を受けているとき）だけ有効にし、それ以外は止める
- 自己診断: ログ（例 `AuraGeo`）に、VPS の状態、精度、使っている「もと」（VPS / GPS）、切り替えの理由を出す（緯度経度は出さない）。`scripts/device-check.sh` に `--only geospatial` を足す（`bash -n` で文法だけ確かめる）。屋外でしか試せないことは、最終報告の「ユーザーに確認してほしいこと」に手順として書く

## 確認手順

1. `./gradlew test assembleDebug` が通る（JDK 21）
2. 単体テスト: 「もと」の選び方（RUNNING と精度の境目 5m・5°、追跡が途切れたら GPS、同意が無ければ GPS、VPS が使えない場所なら GPS）、切り替え時の滑らかな移動、北の向きの「もと」の切り替え、有効にする条件（案内中・信号の受信中だけ）
3. Robolectric の表示テスト: 初回の利用の確認が出て、`使う` / `使わない` の答えが保存されること。答えのあとは出ないこと
4. 既存のテストがすべて通る
5. **実機（adb）は使わない（インストールもしない）**。オーケストレーターが受け入れ中なので、main のワークツリーには触らない
